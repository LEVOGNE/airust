# BM25 evidence selection

AIRust 0.4.5 keeps the existing Engine rankings and default retrieval JSON. Explicitly request `RetrievalOptions::with_distinct_evidence()` and `ExcerptOptions::with_paragraph_boundaries()` when constructing compact evidence for an answer. BM25 remains the source ranking; these options add no embedding, model or database requirement.

Paragraph mode first determines the existing relevant window. A shorter complete block is eligible only if it preserves every distinct query term matched in that window and all retained phrase-hint ranges. Eligible blank-line-separated blocks use the existing phrase-first, distinct-term-count, occurrence-count ordering, with the earliest block breaking ties. A linear sweep visits each match once and retains small term-marker arrays. If no eligible complete block fits, the existing grapheme-safe window remains the fallback. Blank lines may contain whitespace, and LF/CRLF are preserved. Source text and offsets are never rewritten. This lexical coverage safeguard does not prove answer completeness: qualifications without matching query words may still lie outside the result. It cannot repair a chunk whose original input already starts in a cut paragraph.

Distinct delivery removes only byte-identical selected excerpts and fills the remaining result slots from the already retrieved candidate list, in its existing order. It does not compare bags of words, merge negation, infer semantic equivalence, issue more queries or change BM25 scores. The first ranked source is retained. IDs, source ranks, excerpt positions and original evidence stay attached to their actual source entries. Deduplication is inappropriate when separate corroborating sources with identical wording must be retained; leave the option off for that use case.

Discarded duplicate excerpts do not spend delivered text bytes. Empty excerpts are skipped, and exhausted text budgets stop selection. Candidate validation and authorized scope still apply before selection. The initial source candidate cap bounds possible refills. Reranking, when explicitly configured, limits which candidates reach this stage; request sufficient reranker outputs if refill is needed. Source and reranker errors remain errors.

An optional `selection` object reports `considered`, `duplicates_skipped` and `kept_before_output_budget`. The complete JSON budget can subsequently remove tail hits; use the final `hits()` list for delivered IDs. Diagnostic counters describe attempted selection, not total relevant documents. The default response omits this object. `without_distinct_evidence()` restores ranked-prefix delivery. Selection does not establish sufficient evidence or answer correctness.

Validate final model references against the exact delivered response with the [citation API](CITATIONS.md). Measure both answer quality and tokens before enabling compaction. The retained comparison separates exposed regression questions from newly authored holdout questions; neither is an independently adjudicated production workload.
