# Build the comparison workers

The public `worker-baseline.toml` and `worker-candidate.toml` manifests pin the two registry versions and declare the benchmark-only `candidate` feature. Copy each to a separate private folder as `Cargo.toml` and copy `benchmark-worker.rs` beside it as `worker.rs`. Before release, the candidate dependency used an explicit path to the tested checkout; after publication its exact registry version is available. The independent public-API application is separately described in [README](README.md).

Set `CARGO_TARGET_DIR=/private/tmp/airust-evidence-045-build` to match the supplied Python harness, then build the baseline with `cargo build --release --locked` and the candidate with `cargo build --release --locked --features candidate` from their respective directories. Retain the two Cargo locks. For a fresh reconstruction, first generate each lock and compare dependency versions against the retained experiment locks. The measured binaries use the default consumer release profile and the recorded compiler; do not substitute profiler/debug timings. Rebuilding on a different machine or compiler need not reproduce exact timing.

The Python benchmark defaults to `local-lab/evidence-0.4.5`; set `AIRUST_BENCH_DIR` to the retained `final` directory for the 210-question experiment. It requires frozen `plan.json`, `questions.json`, `chunks.json`, `inventory.json`, `frozen-sha256.json`, the earlier verified document vectors/embedding manifest and the existing local models. `questions.json` carries query IDs, project scope, question text, lexical terms, answerability, authored fact checks, reference IDs/quotation and partition. `chunks.json` carries IDs, project, source path, original text and common lexical tokens. All inputs are private, retained and not bundled; the [measurement disclosure](../measurements/0.4.5/README.md) explains the external reproducibility limit. Do not replace them while claiming to rerun the same experiment.

Run `prepare`, `retrieve`, then `answer` with the retained NumPy environment and isolated Ollama server. Finally run `analyze.py` with the same `AIRUST_BENCH_DIR`. Preserve malformed or unsupported answers rather than retrying based on quality. Close workers, stop the owned server and archive the resulting inputs, logs, model metadata, answers and measurements before removing the dedicated Cargo target.
