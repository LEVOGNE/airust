# AIRust 0.2.7 implementation plan

Baseline: published, artifact-verified 0.2.6 at `42051e2`. Add independent `versioning = ["serde/rc"]`, with shared immutable change metadata and no new dependency, mandatory journal, database or application integration. Existing entries, exact/ANN retrieval, cache and provenance formats remain unchanged.

`VersionedIndex` owns an existing lexical engine plus revision heads/tombstones. Writes require `ExpectedRevision::Absent` or `Exact(Revision)`; no implicit force-write path is added. Revisions are checked positive u64 sequence values, monotonically assigned within this index lineage. Tombstones retain the last revision so deleting/reusing an ID cannot bypass conflict checks. Optional caller-supplied actor/reason/metadata describe changes; no external clock or unverifiable audit claim is invented.

The default history capacity is zero. Opting into a bounded global change journal retains committed entry snapshots and metadata, including deletion states, for comparison/restoration. This deliberately copies retained historical text only when requested. Current records stay in the existing engine; query results borrow it. History is bounded by record count, not bytes. Applications choose a capacity and remain responsible for durable history, permissions and source truth.

`upsert`, `delete` and `restore` check expected state and counter exhaustion before mutation. Invalid entries, missing/pruned revisions and stale expectations leave current data, sequence and journal unchanged. Restore uses a retained snapshot or the current state and creates a new revision; it never rewinds the counter. A comparison API reports text, metadata and existence changes between available states. Immutable index access permits existing retrieval/cache APIs; no mutable escape can bypass revision bookkeeping. Consuming `into_index` explicitly ends this wrapper's version history.

Versioned JSON has an independent format identifier and validates original entries, unique heads, exact live/deleted ID agreement, revisions/counter/action consistency, journal bounds/order/IDs and current-snapshot consistency before returning an index. Input defaults to a 16 MiB cap with an explicit override; generic Serde validates structure under the caller's resource policy. Existing portable source-entry JSON remains unchanged. Serialization preserves tombstones and retained history; loading reconstructs the lexical index from current originals.

Tests cover repeated updates, delete/recreate and tombstones, stale writes, two concurrent callers, restore after pruning, source/metadata comparisons, error atomicity, sequence exhaustion, malformed/duplicate/inconsistent imports and format compatibility. Run a 1k/10k/100k update/history benchmark with query agreement against a fresh current-record rebuild, and record memory/export costs. Repeat full local/package/MSRV/consumer/CI/public artifact gates before 0.2.8. These generic versions do not substitute for an application's SQLite transaction, map revision, semantic-vector refresh or provenance invalidation.
