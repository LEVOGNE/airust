# AIRust 0.3.4: Faster PDF object loading

The optional PDF importer now uses a maintained backend with bounded lookahead for complete small objects on long physical lines. It preserves the complete structure tree, source bytes, decryption, caches and original fallback. A byte-safe object-keyword check also removes the known UTF-8 slice panic. Existing library methods, CLI limits and output formats keep their API. See [implementation, API and limits](PDF-PARSER.md).

The matched five-sample CLI comparison improves the known 494-page case from 23.362 seconds to 0.582 seconds in the median, about 40 times faster. A 68-page case improves from 0.501 to 0.088 seconds. The 913- and 2,488-page comparisons remain similar. All 40 paired JSON outputs match. All 8,960 raw pages and 33,708 imported chunks preserve checked text, provenance, counts and rankings across the fifteen-document corpus. These results do not establish a universal speedup or extraction correctness for every PDF.

Ten backend regression tests include structure completeness, differential object/text results, stream/large fallback, Unicode, fixed-seed probes and parallel file loading. Linux CI found duplicate C exports during coexistence tests; the maintained backend now keeps its C ABI opt-in. A second CI issue in the provenance tool was fixed by filtering metadata to the validated host, avoiding unrelated offline platform downloads. The 4,096-case mutation campaign has zero parser panics or unexpected parent exits, with all failed-import outputs preserved. Two newly recovered mutations and their independent reference results remain visible in the measurements. The final main-checkout CLI also passes the retained 134 malformed-input cases and an owned-worker SIGKILL test, preserving previous output and reaping the child. Current AIRust reopens the retained 33,708-entry canonical knowledge index and returns ten bounded hits.

The optional independently named backend is published and validated before the main crate. Its source hashes, notices and small patch are checked automatically. Main and backend archives retain separate source-commit identities. No DenkMaps/MCP integration, model dependency or 0.4.0 expansion is added. The existing knowledge and all raw measurements remain local.

The full check script passes 197 default and 688 all-feature tests, five Python tests, compiled examples, all 37 isolated feature entries and strict lint/docs. Ten backend regressions also pass. Rust 1.89/1.92, 229 patch API checks against 0.3.3 (31 tool skips), a fresh audit and an independent local consumer pass. Clean package/extracted tests and dry-run remain publication gates. Exact-commit CI precedes publication; the registry consumer and checksum/VCS/tag/asset equality are verified afterward. See [reproduction](validation-0.3.4/README.md) and [measurement files](measurements/0.3.4/).
