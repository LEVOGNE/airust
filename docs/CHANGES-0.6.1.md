# AIRust 0.6.1 — Bounded configuration and lower measured memory costs

This is an **unreleased development candidate**. Published 0.6.0 and its tag/package/evidence are unchanged. Publication of 0.6.1 needs its own release instruction.

The work follows an actual local-model pilot before adding configuration. Four real conversation inputs were evaluated over 18 current project documents with BM25, hybrid, hybrid/rerank and Qwen3.8:27b. Complete raw answers, exact source ranges, a generated quote mismatch and a confident historical-roadmap answer are retained. This is exposed local evidence, not independent customer traffic or judgments. The separately frozen 150 authored questions remain regression controls.

The native investigation compared existing CPU-thread and batch controls with the same model, original text, 20-candidate prefix and max512 pair recipe. Smaller outer batches avoid padding every document to the longest document in a larger batch. Results and all numerical/ranking/latency differences belong in [the measurement record](measurements/profile-practical-0.6.0/README.md); a tunable setting alone is not a speed claim. Full-request confirmation and interpreter/native checks are recorded separately.

The overnight extension adds measured training-snapshot sharing, regular-file input bounds, an opt-in verified native snapshot and a small model-free MCP host. It follows the user's priorities of memory safety, performance, robustness and honest evidence. It does not advance all later roadmap versions or manufacture a release.

## Implemented behavior

- The reference `hybrid_rerank` JSON can specify `reranker.batch_size` in 1..16 and `reranker.candidates` in 1..100. Existing validated `RerankOptions` execute those settings; no new scorer, database, tensor framework or global configuration facade is added.
- Missing `batch_size` keeps 16. Missing/null `candidates` keeps the original automatic max(20, requested result limit), including application-owned MCP callers requesting more than 20 results. An explicit candidate budget is not expanded by a larger result request; that request fails before model work and cannot become lexical fallback.
- Cancellation remains checked before request-specific configuration processing/model admission. Original scope, source-revision checks, ownership, failure policies and deadlines remain.
- `reference_workspace profile-check CONFIG` validates the bounded JSON and reports effective settings/relative paths without loading a workspace/cache/native runtime or contacting a service. It requires `pilot`; output is capped at 32 KiB. This is configuration preflight, not an assertion that assets or an inference service are available.
- `KnowledgeBase` clones/from-embedded reuse private shared examples and copy on mutation, preserving logical independence and the save format. An explicit `load_bounded` adds regular-file/byte checks without silently capping the existing trusted-file `load` API.
- A private bounded file reader serves training input, MCP startup and E5 assets. Oversized/special/changing inputs fail before publishing a new object. E5 has model/tokenizer/config caps before native initialization; unchanged valid assets retain the original recipe framing.
- Restoration/import boundaries cap large serde data diagnostics at 2048 UTF-8 bytes while retaining category, line and column. Invalid-UTF-8 rejection retains only the position error. Forty-five old/pre-fix/fixed controls retain both the released large-JSON retention and a caught candidate-only UTF-8 regression, together with the corrected results. Input buffers and transient parser allocations have separate limits.
- `FastEmbedReranker::multilingual_minilm_v2_from_snapshot` and optional `reranker.model_snapshot_directory` stream/verify a private model copy for file-based native loading. Missing/null retains the memory-backed constructor. Lower observed RSS has disk/startup tradeoffs; normal/error cleanup retains original files. Abrupt termination can leave the private temporary copy.
- `bounded_mcp` demonstrates existing data/transport/admission budgets with one CPU worker, no model dependencies and a portable three-slot blocking pool for stdio/compute. The stdio integration suite caught and retains an initial one-thread starvation failure. [Resource ownership](RESOURCE-LIMITS.md) explains exact limits, first-write costs, raw probes and the unverified 1-GiB-device boundary.
- [CONFIGURATION.md](CONFIGURATION.md) maps existing defaults, validation, ownership and feature interactions. The small default Engine API and feature set remain unchanged.

Read [migration](MIGRATION-0.6.1.md), [pilot usage](PILOT.md) and [validation](validation-0.6.1/README.md). Tests cover legacy defaults, explicit budgets, invalid/unknown fields, relative paths, no-network preflight, cancellation priority, non-fallback configuration errors and supported feature/compiler boundaries. Actual command results, including any failed attempts, govern completion.

## Limits

CPU/batch choices are workload/hardware-dependent and can change floating-point outputs slightly; retained comparisons use declared numerical tolerances and list every ranking/labeled-reference loss. The native adapter still has an internal maximum batch of 16 and a maximum combined pair length of 512 tokens. Smaller batches do not recover candidates outside the first-stage prefix or restore truncated text. Extra threads consume more CPU resources; do not treat a wall-time gain as an energy-efficiency measurement.

Local LLM quotations require exact verification. Valid quotations do not establish a complete or correct answer. Three historical question replays and one current improvement request do not supply the minimum 50 genuine independently reviewed cases. Independent onboarding/reproduction and a new production-profile recommendation remain open. Native ONNX/Metal/HTTP execution is outside Miri. The revised finite interpreter scope has 121 passing cases across eleven observed groups; two earlier macOS directory-sync attempts remain unsupported, with successful durability controls checked natively. Selected full lexical/PDF/training libFuzzer scopes passed (90/90/60 minutes); only lexical/training have AddressSanitizer. The original partial PDF corpus-I/O exit remains failed, with a separate full recovery rather than stitched durations. [Validation](validation-0.6.1/README.md) and [final-binary confirmation](measurements/configuration-0.6.1-final/README.md) retain all numerical/resource boundaries. No universal performance/safety/quality claim is made.

Repeated native model loading failed the declared RSS-growth budget twice under the default macOS allocator. A separate optional process-launch allocator experiment reduced retained pages, but is not a library default or an active-model 1-GiB guarantee. All failures, allocator observations and unmeasured deployment costs remain in the resource and measurement guides.
