# AIRust 0.2.5 implementation plan

Baseline: published, artifact-verified 0.2.4 at `dc9e98a`. Add a versioned derived-index cache. Original application records remain authoritative. No database synchronization, storage backend, ANN or revision journal is introduced in this stage.

Reuse the existing safe atomic-file writer. Extend its private implementation with a streaming callback and a cache-specific private-permission policy while preserving existing JSON writes. New cache files and replacements use mode 0600 on Unix. Write an exclusive temporary file, sync it, rename, then sync the parent directory. Never replace a symlink or nonregular destination.

The optional `cache` feature enables existing SHA-256 and Postcard 1.1.3 with only `use-std`. Postcard is MIT/Apache-2.0 and has a documented stable 1.x wire format. Its typed compact representation suits derived strings/counts/f32 vectors; no dynamically typed source metadata is encoded. Existing JSON remains the portable knowledge export. MessagePack (`rmp-serde 1.3.1`) was also reviewed; the cache's fixed versioned Rust schema does not need a self-describing general metadata format. No third-party implementation is copied.

`IndexCache` holds a path, validated dataset identity/optional committed-source revision, and limits. It saves a lexical engine or, when embeddings are enabled, its semantic index. Load methods require the original records and an expected embedding space for semantic caches. The input `Vec<KnowledgeEntry>` is consumed only after complete validation succeeds; failure leaves it available for rebuilding without a corpus clone. Returned `CacheLoad<T>` owns the rebuilt memory structures and exposes cache metadata.

Hash original records sorted by ID, including original text and metadata. Check identity, source fingerprint, format version, text-analysis recipe and optional model recipe/dimension. Include both standard-library and NFKC Unicode table versions in the analysis signature so toolchain Unicode changes invalidate derived data. Store normalized text, per-document token frequencies and lengths, plus optional vectors. Reconstruct posting/duplicate lookup trees from cached frequencies, without repeating normalization, tokenization or inference. Do not store a second authoritative copy of source records.

A fixed 64-byte header contains magic, format/analysis versions, kind, payload length and SHA-256. Check file size before allocation, exact length, checksum, decoder trailing bytes, entry IDs/counts, frequency/length arithmetic, vector IDs/dimensions/finiteness/normalization and expected source/model state. Default limits cap file bytes, entries and dimensions; callers can choose tighter limits. Streaming writes enforce the byte limit before publication. A checksum detects accidental damage, not an attacker who can rewrite and rehash a private cache. Permissions and original-record ownership remain application responsibilities.

Tests cover cold/repeated loads, identical BM25/TF-IDF/matching/duplicate/relation/scoped/semantic results, failed-load source retention, updates/deletes and resaving, incompatible recipes, corruption/truncation/oversize/trailing data, malformed derived structures and vectors, symlinks/nonregular paths, interrupted writes and a killed writer before rename. Compare startup/rebuild on 1k/10k/100k records and record memory plus cache size. Full local/package/toolchain/consumer/CI checks and publication verification precede 0.2.6.

Primary references: [Postcard wire specification](https://postcard.jamesmunns.com/wire-format), [Postcard manifest/license](https://docs.rs/crate/postcard/1.1.3/source/Cargo.toml.orig), [streaming serializer](https://docs.rs/postcard/1.1.3/postcard/fn.to_io.html), [checked remainder decoding](https://docs.rs/postcard/1.1.3/postcard/fn.take_from_bytes.html), and [MessagePack alternative](https://docs.rs/crate/rmp-serde/1.3.1).
