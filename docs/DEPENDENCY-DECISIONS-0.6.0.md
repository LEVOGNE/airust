# Dependency maintenance decisions for 0.6.0

Reviewed on 2026-11-24. The new pilot feature uses already locked reqwest plus its blocking feature; it introduces no new dependency versions. Default features remain empty. No advisory is ignored or marked fixed by these decisions.

| Notice and selected path | Decision and replacement gate |
| --- | --- |
| [chrono / RUSTSEC-2026-0543](https://rustsec.org/advisories/RUSTSEC-2026-0543.html): root optional web, maintained PDF backend, rmcp 3.11.0 and rmcp → schemars 1.2.3 select chrono 0.4.45. | The advisory lists no patched release and names jiff/time as alternatives. Replacing only AIRust's web timestamp formatter would leave the MCP/backend paths. Retain the compatible lock for this milestone. A full migration needs reviewed upstream rmcp/schemars/backend changes, preserved timestamp JSON/format behavior, Rust 1.89 checks, real HTTP/MCP tests and backend provenance gates. No claim that this maintenance notice is resolved. |
| [paste / RUSTSEC-2024-0436](https://rustsec.org/advisories/RUSTSEC-2024-0436.html): fastembed 7.7.1 → tokenizers 0.23.2 → paste 1.0.15. | No patched paste release is listed. pastey/with_builtin_macros are suggested alternatives. The selected invocation belongs to upstream tokenizers; a renamed transitive proc macro is not a lockfile-only compatible upgrade. Prefer an upstream tokenizers/fastembed release replacing it. Require pinned-asset native reranker checks, tokenization parity, all-feature Rust 1.92 checks and measured end-to-end costs before updating. |
| [ttf-parser / RUSTSEC-2026-0192](https://rustsec.org/advisories/RUSTSEC-2026-0192.html): airust-pdf-backend 0.3.5 → ttf-parser 0.25.1. | The advisory lists no patched release and suggests skrifa. Parser APIs and font behavior differ; substituting the crate name would not preserve the backend. Keep the exact maintained backend unchanged. A separate backend change must establish font/parser regression parity, bounded malformed-input behavior, corpus/fuzz checks, provenance/licenses, C ABI/MSRV gates and its own release before repinning AIRust. |
| [anymap2 / RUSTSEC-2026-0319](https://rustsec.org/advisories/RUSTSEC-2026-0319.html): optional backend OCR/tract graph in the retained lock → tract-onnx/tract-nnef/tract-linalg 0.22.5 → liquid/liquid-core 0.26.11 → anymap2 0.13.0. | anymap3 is the recommended replacement; no patched anymap2 release is listed. The package is not selected by the default maintained-backend build. Retain the lock and warning so optional/comparison provenance stays auditable. An upstream liquid/tract update needs the optional OCR feature's full dependency graph and output tests; do not erase the lock entry or present default-build exclusion as a fix. |

The reverse-dependency graphs for the current root all-feature build are retained in `local-lab/pilot-0.6.0/dependency-*.log`. The retained 0.5.3 audit used cargo-audit 0.23.0 and RustSec database revision `1d328b6bb9f2f350bf65c1c81ab68781cb9e018a`: zero known vulnerabilities in both locks with the maintenance notices above. That describes its recorded snapshot, not a perpetual security guarantee. Current advisory pages were checked for these decisions. The new version's final validation record must separately identify any repeated audit, its exact lock hashes and database snapshot.

Original knowledge, databases, backend source and historical rejected trials are retained. These are reviewed compatibility/upstream decisions, not a statement that unmaintained dependencies are desirable or harmless. Re-evaluate them when compatible upstream replacements or a concrete defect become available.

The repeated 0.6.0 lock audits used the same tool/database revision and again reported zero known vulnerabilities, with three root and four backend maintenance notices. Exact lock/tool hashes and raw-report identities are retained in the new validation evidence. A package-identity comparison with the audited 0.5.3 root lock found no changed third-party name/version/source/checksum tuples.
