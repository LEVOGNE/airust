# AIRust 0.4.11 retained results

Read the [report](../../CHANGES-0.4.11.md), [method/programs](../../validation-0.4.11/README.md), [API/performance](../../CORE-PERFORMANCE.md) and [MCP boundaries](../../MCP.md).

- Query records cover 25 fixtures, 282,800 timed calls in fourteen plain processes and 5,000 calls in two separate instrumented runs. Sparse widths 33/128/512 and the original 32/33 boundary are retained. All slower and higher-byte cases remain.
- `norm-memory.json` separately measures cold norm-hint allocation traffic and retained bytes after dropping results; source/index setup is excluded. Fewer blocks can coincide with more retained or cumulative bytes.
- MCP original/confirmation records retain both preplanned campaigns: sixty actual servers, 5,720 schema-valid responses and 2,860 structured comparisons. Initial first-pass and repeated samples are distinct, with first TF-IDF calls available separately. This new method applies equally to both versions and differs from older mixed-state tables.
- Retrieval records cover the same 342 exposed questions, three BM25 configurations,1,026 complete JSON comparisons and10,260 timed samples. Scalar outcomes contain no passages. No fresh quality judgment is added.
- Construction records retain 40 plain processes / six separate profiles as controls. Corpus records retain update/rebuild/roundtrip/concurrency/export identity; fixed source-code query strings are omitted from public copies.
- Frozen/extended input hashes, method/binary identities, validation and resource/host-activity records preserve conditions. Stage-start snapshots are not continuous isolation measurements. Hashes identify supplied data rather than authenticating truth.

Baseline is exact registry 0.4.10; candidate is 0.4.11. Warm canonical TF-IDF improves here, isolated sparse broad queries improve more, while small transports, several other microfixtures and hint allocations have costs. Public aggregates cannot reconstruct private documents. Raw transcripts/profiles/source snapshots and exact binaries/locks remain private and preserved. No DenkMaps integration, new model replies, holdout labels, semantic-quality or PDF parser claim.
